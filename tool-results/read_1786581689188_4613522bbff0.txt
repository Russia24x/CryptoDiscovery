     1→# Crypto Market Discovery Framework — Worklog
     2→
     3→## Project Overview
     4→
     5→A comprehensive Python-based crypto market discovery & analysis framework
     6→exposed through a Next.js dashboard. The user can configure discovery lenses
     7→(persona, market-cap range, sectors) and trigger a market scan on demand.
     8→The framework implements all 8 phases of the provided Persian-language
     9→specification: Discovery → Screening → Evidence → Evaluation → Scoring →
    10→Investment Analysis → Decision → Output.
    11→
    12→## Architecture
    13→
    14→```
    15→Next.js UI (port 3000)  ──API proxy──▶  Python FastAPI (port 3003)
    16→   src/app/page.tsx                      mini-services/crypto-scanner/
    17→   src/app/api/scanner/*                 ├─ main.py            (FastAPI app)
    18→                                         ├─ models/schemas.py  (Pydantic)
    19→                                         ├─ data/sources.py    (CoinGecko+DeFiLlama)
    20→                                         └─ framework/
    21→                                            ├─ core.py         (principles, veto, persona weights)
    22→                                            ├─ discovery.py    (PHASE 1 — 5 lenses)
    23→                                            ├─ evidence.py     (PHASE 3 — evidence collection)
    24→                                            ├─ evaluation.py   (PHASE 4 — 5 axes scoring)
    25→                                            └─ analysis.py     (PHASE 5-8 — scoring + output)
    26→```

    57→## Key Implementation Decisions
    58→
    59→1. **Data sources**: Used free public APIs (CoinGecko + DeFiLlama) — no API keys
    60→   required. CoinGecko is rate-limited (429s) so we gracefully fall back to
    61→   DeFiLlama-only discovery. The framework correctly lowers confidence when
    62→   evidence is sparse (by design — "never hide uncertainty behind a precise-
    63→   looking score").
    64→
    65→2. **Overview data reuse**: Instead of making per-protocol API calls (which were
    66→   slow and caused timeouts), we fetch the DeFiLlama protocols + fees overview
    67→   lists ONCE during discovery, then pass the cached data to the evidence
    68→   collector. This made scans ~10x faster (12 projects in ~7 seconds).
    69→
    70→3. **Conservative scoring**: The framework is intentionally skeptical. Projects
    71→   with missing data get low scores AND low confidence. This is the correct
    72→   behavior per the specification (Evidence > Narrative).
    73→
    74→4. **Python watchdog**: The sandbox kills bash-based background processes between
    75→   commands, but Python daemons survive. So we use a double-fork Python daemon
    76→   (`watchdog.py`) to keep the Next.js dev server alive.
    77→
    78→## How to Use
    79→
    80→1. The Python scanner service runs on port 3003 (started by `mini-services/crypto-scanner/start.sh`)
    81→2. The Next.js dev server runs on port 3000 (kept alive by `watchdog.py`)
    82→3. Open the app in the Preview Panel
    83→4. Configure persona + market cap range + sectors in the left sidebar
    84→5. Click "Scan Market"
    85→6. Watch the 8-phase progress
    86→7. Click any project card to see the full 23-section analysis report
    87→
    88→## Unresolved Issues / Risks
    89→
    90→1. **CoinGecko rate limits**: The free CoinGecko API returns 429 frequently.
    91→   We handle this gracefully (fall back to DeFiLlama), but tokenomics data
    92→   (market cap, supply, etc.) is sometimes missing. A CoinGecko API key would
    93→   fix this.
    94→
    95→2. **Conservative scores**: Current scores are low (most projects 10-30/100)
    96→   because the framework penalizes missing evidence heavily. This is by design
    97→   but may surprise users. The confidence column helps interpret this.
    98→
    99→3. **In-memory storage**: Scan results are stored in Python process memory.
   100→   If the scanner service restarts, results are lost. For production, persist
   101→   to SQLite.
