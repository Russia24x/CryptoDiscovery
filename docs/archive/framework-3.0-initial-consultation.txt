هسته‌ی Framework 2.0 بسیار مهم است: `Discovery → Veto → Evidence → DD → Valuation → Thesis → Action` و تفکیک صریح `Project Quality ≠ Token Quality ≠ Investment Attractiveness`.  همچنین فایل دوم همین معماری را به‌عنوان یک فرآیند ۲۴ فازی و با اجرای داده‌ی زنده تثبیت کرده است. 

اما فریم‌ورک اول چند قابلیت مهم دارد که در Framework 2.0 باید حفظ شوند: **Market Regime، Top Protocols، P/R، P/F، P/T، Macro، ETF، Stablecoin، F&G، DXY، Tier Funnel و Cross-Verification**.

یک اصلاح مهم هم انجام می‌دهم: فرمول ساده‌ی `Adjusted = Score × (1−unlock) × (1−gov)` را به مدل **Risk Adjustment مستقل و محدودشده** تبدیل می‌کنم؛ چون در فرم فعلی می‌تواند یک ریسک متوسط را به‌صورت غیرخطی و بیش‌ازحد Score را نابود کند. همچنین `Fees × 12` را به‌عنوان **annualized run-rate** معرفی می‌کنم، نه Revenue واقعی.

# UNIVERSAL RULES

1. هرگز داده جعل نکن.
2. هرگز مقدار گمشده را حدس نزن.
3. هر عدد مهم باید Source + Date داشته باشد.
4. هر ادعای مهم باید Evidence داشته باشد.
5. Partnership ≠ Revenue.
6. Volume ≠ Revenue.
7. Revenue ≠ Profit.
8. Revenue ≠ Token Value Capture.
9. TVL ≠ Product-Market Fit.
10. Social Attention ≠ Adoption.
11. یک Transaction ≠ Durable Signal.
12. داده قدیمی باید Label شود.
13. عدم‌قطعیت نباید پشت عدد دقیق پنهان شود.
14. Weighted Average نباید Weakness بحرانی را پنهان کند.
15. Evidence نباید Double Count شود.
16. Primary Evidence از Secondary Evidence جدا شود.
17. Project Quality از Token Quality جدا باشد.
18. Token Quality از Valuation جدا باشد.
19. Valuation از Timing جدا باشد.
20. پروژه با Peer واقعی مقایسه شود.
21. Thesis Kill Conditions الزامی است.
22. بعد از Material Event دوباره Score کن.
23. Stablecoinها را از Tokenهای عادی جدا کن.
24. Exchange Tokenها با `*` مشخص شوند.
25. هر عدد بزرگ باید «یعنی چی؟» داشته باشد.
26. Score بدون Confidence کافی قابل اتکا نیست.
27. `N < 10` در نمونه‌های آماری → `⚠️ Approximate`.
28. MC/TVL با منبع دوم Cross-Verify شود.
29. اختلاف >15% → `🔴 Data Discrepancy`.
30. Fees Volatility بالا → Annualized Fees با احتیاط.
31. Underfollowed ≠ Undervalued.
32. Regulatory Compliance ≠ Regulatory Moat.
33. No Token ≠ Bad Project.
34. Action ≠ Score.
35. هیچ‌گاه از عبارت‌های «حتماً»، «قطعاً» و «انقلابی» برای پیش‌بینی استفاده نکن.
36. هیچ‌گاه یک عدد زنده را از حافظه بازتولید نکن.
37. اگر داده زنده در دسترس نیست، صریحاً بگو.
38. در تحلیل زنده، Data Cutoff را اعلام کن.
39. هر بخش باید یک خط «یعنی چی؟» داشته باشد.
40. خروجی نهایی باید فارسی و RTL-friendly باشد.
